# 引用计数与循环回收（从 0 实现）

本仓库是起始环境：只有规格、操作脚本、期望输出与现场记录，没有实现代码。目标是从 0 写一个确定性的「引用计数 + 循环回收」运行时：命令行用 Python 3.13 标准库，回放页面用原生 ES module，无第三方依赖、无构建步骤。

## 1. 范围

要做：仓库根目录的 `main.py`（读脚本、逐句执行，输出轨迹与每步存活集合，回收语义由自己维护的计数与图结构产生）；`web/index.html`（原生 `<script type="module">`，无构建、不加载外部资源，可选择或拖入脚本逐步回放）。

不做：不解析真实编程语言，输入只有下面六种操作；不做并发/增量回收、持久化、业务集成；不得借用运行时的垃圾回收能力（`gc`、`weakref` 等模块一律不用）；页面不做移动端适配、不联网；不得读取 `samples/expected/**`，不得按用例名或内容特判。

## 2. 口径与公式

- 对象名字唯一且不可复用，语法 `[a-z][a-z0-9_]{0,31}`；名字一旦出现（含已释放）就不能再 `new`。
- 外部持有 `ext(x)`：`new x` 计 1 次，`pin x` 加 1，`unpin x` 减 1。
- `ref a b` 增加一条有向边 a→b（允许重边与自环），`unref a b` 删除其中一条。
- `cnt(a→b)` 为现存边条数；`int(x) = Σ cnt(y→x)`（y 只取存活对象）；`rc(x) = ext(x) + int(x)`。
- `rc(x)` 归零必须立即释放，不等 `collect`；释放时删除其全部出边并递减目标 `int`，可能连锁。
- 不变量（每一步结束后都成立）：计数守恒（`int(x)` 与全图入边条数一致）；无悬挂引用（每条边两端都存活）；已释放对象不可再引用（对已释放名字报 `dead`，从未创建的报 `unknown`，都终止脚本）；`rc > 0` 只表示有入边、不代表可达；事件顺序只由脚本与名字字典序决定，不依赖哈希顺序、插入顺序或时钟。

## 3. 数据结构与状态机

对象表只放存活对象：`name → {ext, int, out: {目标名: 边数}}`，配套存活集合、已用名字集合、FIFO 待释放队列、步号。

| 操作 | 前置检查（从左到右，不过则报错终止） | 效果 | 事件 |
| --- | --- | --- | --- |
| `new x` | x 从未出现过 | 建对象，`ext=1` | `+x` |
| `pin x` | x 存活 | `ext += 1` | 无 |
| `unpin x` | x 存活且 `ext > 0` | `ext -= 1`；`rc==0` 则释放 | 可能 `-x,…` |
| `ref a b` | a、b 都存活 | 加一条 a→b | 无 |
| `unref a b` | a、b 都存活且存在 a→b | 删一条；目标 `rc==0` 则释放 | 可能 `-b,…` |
| `collect` | 无 | 见下 | 可能 `-…` |

错误码六个：`syntax`（解析失败或参数个数不对）、`redefine`（`new` 用了出现过的名字）、`unknown`（从未创建）、`dead`（曾创建但已释放）、`noedge`（要删的边不存在）、`underflow`（`ext` 为 0 还 `unpin`）。报错语句不改变状态，脚本当场终止。

释放顺序：全部走同一个 FIFO 队列。某对象 `rc` 归零时入队；出队即移出存活集合、记 `-x`，再按目标名字升序逐条处理它的出边并递减目标 `int`；归零者按处理顺序入队，已在队列里的不重复入队，目标若已释放则跳过。

循环回收（`collect`）：只由脚本里的 `collect` 触发，无自动触发（长期运行的服务要自己安排周期性触发，背景见 `samples/notes.md`）；遍历范围是从所有 `ext > 0` 的存活对象沿出边做完整可达标记，重边不重复访问；未被标记的部分记为 D，D 里必然是一组互引的环及附着其上的对象，按名字升序依次用同一套队列规则释放。

## 4. 输入输出与文件格式

操作脚本（`samples/scripts/*.script`）：UTF-8、LF 或 CRLF；空行忽略；首个非空白字符是 `#` 的整行是注释，不支持行尾注释；语句用空白分隔操作名与参数。步号从 1 起，只数语句行。

轨迹文件（`<用例>.trace.txt`）每步一行 `<步号> <语句> -> <事件>`：

    7 unref a b -> -b,-a
    12 collect -> -

语句是去首尾空白、连续空白压成单空格后的原文；事件为空写 `-`，否则按发生顺序用 `,` 连接，只有 `+名字`（创建）、`-名字`（释放）、`!错误码`（终止）三种。

存活集合文件（`<用例>.live.txt`）每步一行 `<步号> <名字列表>`，列表为该步结束后的存活对象，按名字升序、`,` 分隔，空集合写 `-`。

`samples/scripts/<用例>.script` ↔ `samples/expected/<用例>.trace.txt` 与 `<用例>.live.txt` 一一对应；全部文件 UTF-8、LF、末行带换行；报错用例只写到出错那一步。

命令行：`python3 main.py <脚本路径> [--trace <路径|->] [--live <路径|->]`（Windows 上用 `wsl -- python3`）。`--trace` 默认 `-`（stdout），`--live` 默认不输出，`-` 表示 stdout，两者同时为 `-` 属于用法错误。退出码：0 执行完毕，2 脚本出现错误码（输出写到出错步），1 用法或读写问题。输出须流式写出，不得整份拼接。

页面：`web/index.html`，在仓库根目录 `python3 -m http.server` 后访问（不要求 `file://` 打开）。可选择 `samples/scripts` 里的脚本或拖入本地 `.script`，支持单步、连续播放、重置，显示当前步号与语句、本步事件、存活集合，以及每个存活对象的 `ext`、`int`、`rc` 和出边（目标名、条数，按名字升序）。

## 5. 性能与验收口径

预算（Python 3.13、单核、4 GiB）：50 万条语句、峰值存活 20 万对象时，关闭轨迹输出 ≤ 20 秒、峰值常驻 ≤ 512 MiB；单步操作均摊 O(1)，单次 `collect` 为 O(存活对象数 + 存活边数)；轨迹流式输出，内存不得随步数与历史事件增长；已释放对象的结构要真正断开，允许保留的只有「已用名字」这一个名字集合。

验收：

1. 逐个运行 `samples/scripts`，`--trace`、`--live` 写出的文件与 `samples/expected/` 同名文件逐字节一致（行序、空集合写法、终止位置都要对上）。
2. 重复运行、以及不同 `PYTHONHASHSEED` 下输出逐字节相同。
3. 页面回放的逐步结果与同一份期望一致。
4. 只用标准库，无第三方依赖、无构建步骤、无网络；不得读 `samples/expected/**`，不得按用例名或内容特判。

## 6. 样例说明

`samples/scripts/` 共 13 个脚本，每个与 `samples/expected/` 下同名 `.trace.txt`、`.live.txt` 一一对应：

| 用例 | 覆盖点 |
| --- | --- |
| `01_self_loop` | 自环：外部持有解除后计数不归零，`collect` 才发现并回收 |
| `02_mutual_pair` | 双对象互引：两侧互相支撑，回收按名字升序 |
| `03_long_cycle` | 8 节点长环加附着链：根在时整链可达，撤根后整组回收 |
| `04_cascade_order` | 即时释放的连锁顺序：FIFO 队列加出边按目标名升序 |
| `05_churn` | 频繁增删引用：重边、`pin`/`unpin`、打断环的级联释放与 `collect` 空转 |
| `06_temp_burst` | 150 个创建即释放的临时对象、周期性 `collect`，末尾回收 4 节点环 |
| `07_after_free_ref` | 对已释放对象再 `ref` 报 `!dead` 并终止 |
| `08_after_free_unref` | 对已释放对象再 `unref` 报 `!dead` 并终止 |
| `09_unknown_name` | 从未创建的名字报 `!unknown` |
| `10_redefine_name` | 已释放的名字再 `new` 报 `!redefine` |
| `11_unpin_underflow` | `ext` 为 0 时 `unpin` 报 `!underflow` |
| `12_missing_edge` | `unref` 不存在的边报 `!noedge` |
| `13_bad_syntax` | 参数个数不对报 `!syntax` |

`samples/notes.md` 是现场记录；`samples/**` 只读，不得改动。
