# 性能实测（对应 README 第 5 节预算）

环境：Python 3.14.4（GCC 15.2.0，Linux x86-64），单核，机器内存 16 GiB。
预算口径为 Python 3.13、单核、4 GiB；本机实测留有余量。

## 预算用例：20 万峰值存活、60 万条语句

脚本形态：20 万个对象按 4 个一环组成 5 万个环（new×200k + ref×200k），
解除全部外部持有（unpin×200k），最后一次 `collect` 整体回收。

| 指标 | 预算 | 实测 |
| --- | --- | --- |
| 语句数 | 50 万 | 600,001 |
| 峰值存活 | 20 万 | 200,000 |
| 关闭轨迹输出耗时 | ≤ 20 s | 0.70 s |
| 轨迹流式写文件耗时 | — | 0.71 s |
| 峰值常驻内存 | ≤ 512 MiB | 110.6 MiB |

## 加压用例：90 万条语句（含 30 万次引用抖动、3 次 collect）

形态：同上建环后，先做 30 万次「加一条重边再删掉」的抖动（中途两次
`collect` 空转），再解除外部持有，最后一次 `collect` 回收全部 20 万对象。

| 指标 | 实测 |
| --- | --- |
| 语句数 | 900,003 |
| 关闭轨迹输出耗时 | 1.11 s |
| 轨迹流式写文件耗时 | 1.07 s |
| 峰值常驻内存 | 117.2 MiB |
| 末次 collect 单次回收 | 200,000 个对象（5 万个环） |

## 内存曲线形态

- 建环阶段：存活对象数随 `new` 线性爬到 20 万，RSS 同步爬升。
- 抖动阶段：存活数不变，RSS 平稳（重边只是计数增减，结构即增即删）。
- 解除外部持有阶段：引用计数路径释放不了环内对象，存活数不降——
  这正是现场「内存只涨不跌」的成因。
- 末次 `collect`：存活数一步从 20 万归 0，对象结构全部断开，允许保留的
  只有「已用名字」集合；Python 侧 dict/str 随之可被回收，RSS 落回。

复现方式：`python3 -m unittest discover -s tests` 中的
`PerformanceTest.test_perf_budget` 会重新生成 60 万语句用例并校验 20 秒
预算；轨迹流式输出，内存不随步数与历史事件增长。
